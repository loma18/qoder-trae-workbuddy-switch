# 故障排查（v2.1 · WorkBuddy / Qoder / Trae 三平台独立版）

> 先看「设置 → 运行日志」。App 不打印 token 明文，但会记录每次登录、签到、同步的结论。
> 账号页顶部可按 **全部 / WB / Qoder / Trae** 筛选，排查时先确认账号的平台与区域标签是否正确。

## 1. WorkBuddy 登录

| 现象 | 原因 / 处理 |
|:--|:--|
| 「获取授权链接失败 code=…」 | 手机无法访问官方域（无网络 / DNS 被拦 / 代理）。换网络重试；国内版走 `copilot.tencent.com`，国际版走 `www.workbuddy.ai`。 |
| 一直「等待扫码 / 确认授权…」 | 正常：官方对**未扫码**与**已扫未确认**都返回非 0 业务码（实测 `11217`），没有单独的"已扫码"信号。确认已在浏览器点完「确认授权」，再回 App 点「检查结果」。 |
| 「二维码已过期（5 分钟）」 | 重新点「发起登录」。会话 TTL 5 分钟，超时后旧 state 作废。 |
| 「登录响应的 domain 与档位不符」 | 用国内版申请的码却拿国际版账号授权（或反之）。请确认选的档位与登录的腾讯账号一致，重新发起。 |
| 国际版登录成功却查不到积分 | 检查档位是否选成国内版。两档域名不同，跨档请求只会 401。 |
| 授权页打不开 | 点「复制链接」到浏览器手动打开；或把二维码给另一台设备扫。App 内 WebView 不承载授权页（`shouldOverrideUrlLoading` 会把外部链接交给系统浏览器）。 |
| 扫码后账号没出现 | 登录成功后 App 会自动刷新账号页；也可下拉/切页重进。「设置 → 运行日志」应有「扫码登录成功」。 |

**关键**：这套登录**不需要电脑开着**，也不需要电脑端控制台。手机浏览器完成授权即可。

## 2. Qoder 登录

| 现象 | 原因 / 处理 |
|:--|:--|
| 一直「等待扫码 / 确认授权…」 | 正常。轮询返回 `202` / `404` 代表尚未完成授权，App 会继续轮询，直到 5 分钟 TTL 超时。 |
| 「授权已超时（5 分钟），请重新发起」 | 重新点「发起登录」。 |
| 「拉取账号身份失败：HTTP …」 | token 已拿到但 `GET /api/v1/userinfo` 失败；多为临时网络或区域域名不通，重试一次；仍失败重新发起。 |
| 「账号信息尚未就绪，稍后重试…」 | `userinfo` 响应里没有 `id`。稍等再点「检查结果」。 |
| 国内版授权页打不开 | 国内版 URL 带 `redirect_uri=qoder-work-cn://`，需用系统浏览器打开；也可点「复制链接」。 |
| 换手机/重装后 Qoder 被风控 | `machine_id` 按档位持久化在本机。跨设备会变，属上游机器身份风控；避免频繁换设备登录。 |

Qoder 的 `machine_id`、PKCE verifier、nonce 全部在手机本地生成，`loginStart` **不发任何网络请求**，
因此也不需要电脑。

## 2b. Qoder 签到（v2.1.1 修复「跳过」）

| 现象 | 原因 / 处理 |
|:--|:--|
| **v2.1.0 及更早：签到总提示「跳过 / 该区域暂未开放每日签到接口」** | **这是 Bug，已修复**。旧版只打已废弃的 `/sash/api/v1/me/daily-check-in/*`，该通道国内版 `DISABLED`、国际版 404，遇 404 就返回 `skipped`。升级到 **v2.1.1** 后改走官方活动平台 `GET /sash/api/v1/me/campaigns` → 逐条 `POST /{id}/claim` 领取「每日 100 Credits」。 |
| 「PAT 不能用于活动平台签到，请用发起登录」 | 粘贴了 `pt-` 开头的 PAT。上游不允许 PAT 调用活动平台，**只能查额度**。删除该账号，改用「发起登录」扫码取得 access token。 |
| 显示「**未开放**」（橙色） | 活动列表里**没有积分类活动**，或本区域整区没有活动平台。这是如实结论，**不是成功也不是失败**（不计入「N 个成功」）。可确认账号档位是否正确、活动是否在 10:00–次日 09:59 窗口内；官方把活动改成限时/新人任务时也会如此。 |
| 「今日活动奖励已领取」 | 成功档。上游 `claimStatus=CLAIMED` 或 claim 返回 409 / `ALREADY_CLAIMED`，说明今天已领过。 |
| 「同人已领取」 | 同一设备 / 身份下其他账号本轮已领过，服务端按人去重。属上游规则，6 小时后可再试；换账号无用。 |
| 「名额已发完 / 需先完成新人任务」 | 上游 `failureCode`。每日 10:00（UTC+8）刷新名额；新人任务需在官方桌面端完成。 |
| 「活动列表失败：HTTP 401/403」 | token 失效或身份不被认可。Qoder 手机端不做刷新，请重新「发起登录」扫码。 |
| 国际版活动列表为空 | 上游要求官方原生机器身份（`cosy-machine*` 头），手机没有该组件。App **刻意不发假头**（发派生假头反而会让服务端把可领活动整条过滤掉），此时可能不可见，属已知上游限制。 |
| 签到成功但显示 +0 | 上游 `benefit.amount` 可能是 `100.0` 浮点。v2.1.1 已按浮点解析；若仍为 0，看「设置 → 运行日志」与活动明细。 |

> 排查时先看结果里的**活动明细**（逐条 `领取成功 +N Credits · 活动名`）与
> 「下次可领 MM-dd HH:mm（UTC+8）」，再对照 [API-CONTRACT.md](API-CONTRACT.md) 第 2 节。

## 3. Trae 导入（无扫码）

| 现象 | 原因 / 处理 |
|:--|:--|
| 添加账号时看不到「发起登录」 | **正常且是预期行为**。Trae 上游授权 URL 需要桌面客户端 `storage.json` 解密出的设备私钥，且授权页会探测 `127.0.0.1:17388`，手机无法满足。App 只提供「粘贴 Trae JWT」。 |
| 「JWT 格式不正确」 | 应为 `xxxxx.yyyyy.zzzzz` 三段。可带 `Cloud-IDE-JWT ` 或 `Bearer ` 前缀，App 会自动剥掉。 |
| 「JWT 中找不到用户 ID」 | payload 里没有 `data.id` / `auth_id` / `sub` / `user_id`。后续接口强依赖 userId 派生设备头，请重新导出完整 JWT。 |
| 「签到失败：HTTP 401/403」 | JWT 已过期或被上游拒绝。Trae JWT 由客户端签发，**App 不做手机端刷新**，需从桌面客户端重新导出并粘贴。 |
| 查积分提示「缺少 user_entitlement_pack_list」 | 响应结构变了或账号无权益包；先看运行日志里的 HTTP 状态，再对照 [API-CONTRACT.md](API-CONTRACT.md) 第三节。 |
| 同一账号偶尔签到被限流 | App 按 uid 稳定派生并持久化 `x-device-id` / `x-market-user-id` / `vscode-sessionid`，正常不会变。若曾清过 App 数据，设备头会重新生成，上游可能短暂关联风控，稍后重试。 |

> 首次从桌面客户端导出一次 JWT 后，签到 / 领积分 / 查余额都在手机上完成，此后**不再依赖电脑**。

## 4. 签到 / 领积分（通用）

| 现象 | 原因 / 处理 |
|:--|:--|
| 「token 已过期，请刷新凭据或重新扫码」 | WorkBuddy `daily-checkin` 返回 401/403。账号页点「刷新凭据」用 refresh_token 换新；若 refresh 也已过期（或手动导入时没有 refresh），只能重新扫码。Qoder / Trae 无刷新端点，需重新粘贴 / 导出。 |
| 「今日已签到（code=10001）」 | 成功，不是错误。WorkBuddy 官方对重复签到返回 HTTP 400 + `code=10001`；Qoder / Trae 用 `already` / 「已签」判定，同样视为成功。 |
| 显示「已跳过」 | 正常。WorkBuddy 国际版无签到接口、Qoder 部分区域无签到接口、Qoder/Trae 无成长中心，均跳过且不计入失败。 |
| 显示「未开放」（橙色） | Qoder 活动列表里没有积分类活动 / 整区无活动平台。**不是成功也不是失败**，详见第 2b 节。 |
| 「签到失败 code=…」 | 展示官方 `msg`。偶发风控时稍后重试；不要高频连点。 |
| 成长中心「查任务列表失败」 | 多为登录态或活动接口临时异常；先「刷新凭据」再试。写操作不重试，避免重复领奖。**仅 WorkBuddy 国内版有成长中心。** |
| 自动签到没执行 | ① 设置里开关是否打开；② 是否至少有一个账号；③ Android Doze / 厂商省电策略会延迟 `AlarmManager`，不保证精确；④ 把 App 加入电池优化白名单。自动签到会遍历**全部平台**账号。 |

## 5. 积分

| 现象 | 原因 / 处理 |
|:--|:--|
| 「未配置 access_token」/「凭据为空」 | 手动导入的账号没填 token。删除后重新添加。 |
| 「查询失败 / 登录态已失效」 | 401/403 → 刷新凭据（WB）或重新粘贴（Qoder）/ 重新导出 JWT（Trae）。 |
| 显示「缺 uid」 | 手动粘贴的裸 token 若 JWT 里没有 `sub`，部分接口会拒绝。用扫码登录，或粘贴带 uid 的完整凭据 JSON。 |
| 到期显示「未知」 | `expiresAt = 0` 表示这条记录没带时间，**不等于已过期**。汇总接口本身不含到期字段时如实显示未知。 |
| 「界面不显示 0」 | 查询失败写「查询失败」、缺 uid 写「缺 uid」，不用 0 冒充真实余额。 |
| Qoder「额度响应缺少 userQuota / addOnQuota」 | 响应结构变更，查运行日志与 [API-CONTRACT.md](API-CONTRACT.md) 第二节。 |

## 6. 凭据刷新

| 现象 | 原因 / 处理 |
|:--|:--|
| 「该账号没有 refresh_token」 | 手动导入的裸 token 通常只有 access。重新扫码登录可获得完整凭据。 |
| 「refresh_token 已失效」 | **WorkBuddy 轮换式**：同一账号在别处（如电脑端控制台）刷新过后，本机旧值立即作废。重新扫码，或先在「同步」页做「从电脑同步凭据」把电脑端那份读回来。 |
| access 过期但账号还在 | 正常。`expiresAt`（几小时）与 `refreshExpiresAt`（几十天）是两个时间线，**不能混用**；access 过期只需刷新，refresh 过期才算真失效。 |
| Qoder / Trae 点「刷新凭据」返回跳过提示 | 上游没有对应移动端刷新端点。Qoder 请重新「发起登录」扫码；Trae 请重新导出 JWT。 |

## 7. 可选同步到电脑（仅 WorkBuddy）

| 现象 | 原因 / 处理 |
|:--|:--|
| 「只能填局域网地址…」 | App 只接受私有网段/回环，填公网 IP 或域名会被拒绝（防止长期凭据外发）。 |
| 「连不上电脑」 | ① 手机与电脑同一 Wi-Fi；② 电脑端 workbuddy-console 已开启局域网同步；③ IP 填的是电脑的局域网 IPv4；④ 端口默认 `57900`；⑤ 电脑防火墙放行。 |
| 「配对码不正确」(401) | 电脑端显示的配对码与 App 填的不一致。 |
| 「电脑端不支持该操作（版本过旧）」(404) | 旧版控制台没有 `/api/lansync/fetch`。「推送到电脑」一般仍可用；升级电脑端后可「从电脑同步凭据」。 |
| 同步后某台掉登录 | 见第 6 节轮换式 refresh_token。`fetch` 是只读端点，且手机端只补「已失效」的账号、不覆盖仍有效的，就是为了避免死凭据覆盖。 |
| Qoder / Trae 账号没同步过去 | 预期行为：lansync 的凭据模型只覆盖 WorkBuddy，另两个平台不参与。 |

**同步完全可以不用**：App 的默认状态不连任何电脑，三平台的登录/签到/查积分都在手机上完成。

## 8. 覆盖安装 / 升级（重要）

| 现象 | 原因 / 处理 |
|:--|:--|
| 安装提示「应用未安装」或签名冲突 | 新 APK 与已装版本签名证书不同。本项目 `signing/release.keystore` 固定，指纹锚点 `2092c870…7b6c`；**换机构建必须带上整个 `signing/` 目录**，否则会生成新密钥。 |
| 构建时提示「versionCode 必须依次递增」 | 已有 `dist/agent.apk` 时，`build.sh` 要求新 `versionCode` 严格大于旧值。发新版本请改 `AndroidManifest.xml` 的 `versionCode`（+1）与 `versionName`。 |
| 同一版本只改了 SPA/资源想重建 | 用 `ALLOW_REBUILD=1 ./build.sh`，跳过版本递增检查（签名仍不变，可覆盖）。 |
| 明确要换签名（会要求用户卸载） | `RESET_FINGERPRINT=1 ./build.sh`，仅在你确定放弃覆盖升级时使用。 |
| v1.x 老版本升级 v2.x | v1.x 私钥已丢失，需卸载一次；**v2.0.0(3) → v2.0.1(4) → v2.1.0(5) → v2.1.1(6) 之间可直接覆盖安装**。 |
| 升级后 Qoder 仍提示「跳过」 | 确认「设置 → 版本」是 **2.1.1**；旧版缓存可能残留，重进账号页再点签到。 |

## 9. 演示模式与预览

- 「设置 → 演示模式」用内置假数据浏览全部界面（含 WB / Qoder / Trae 四个演示账号），**不发起任何网络请求**。
- 用浏览器直接打开 `assets/index.html` 时会自动进入演示模式（没有原生桥），方便预览界面。
- 关闭演示模式会重新读取本机真实账号库。

## 10. 兜底

若官方接口变更（路径/字段/风控策略），按平台分别核对最新实现：
- WorkBuddy：[fewards](https://github.com/loma18/fewards) 与 [workbuddy-console](https://github.com/loma18/workbuddy-console)；
- Qoder / Trae：`qoder-trae-workbuddy-switch` dev 分支 `buddy-switch-core/src/modules/{qoder,trae}/*.rs`；
- 再按 [API-CONTRACT.md](API-CONTRACT.md) 更新对应的 `WorkBuddyApi.java` / `QoderApi.java` / `TraeApi.java`。
